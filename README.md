# 国学老师 H5

一个以国学咨询为主题的移动端 H5 原型。项目使用原生 HTML、CSS 和 JavaScript 实现，包含模拟问答、每日对话额度、历史会话以及八字档案管理等功能。

> 当前版本是纯前端演示：回答由本地关键词规则生成，不会请求 AI 或后端服务；档案和会话数据仅保存在当前浏览器中。

## 功能概览

- 国风移动端首页与“今日指引”
- 内嵌问答区和约 700 ms 的模拟回复状态
- 每日 10 次免费对话额度，按浏览器本地日期自动刷新
- 按日期保存和切换历史会话
- 新增、编辑、删除及切换八字档案
- 个人中心抽屉，支持按钮、键盘和边缘滑动操作
- 中文输入法组合态处理、焦点管理和减少动态效果适配
- `chat.html` 兼容旧入口并自动跳转首页

“专业排盘”“国心解读”“学习资料”、语音输入、个人资料和会员服务目前仍是演示入口或占位功能。

## 快速开始

项目没有依赖安装和编译步骤。建议通过本地 HTTP 服务访问，避免直接打开文件时出现浏览器存储或资源加载限制。

使用 Python：

```bash
python -m http.server 8000
```

或使用 Node.js：

```bash
npx serve .
```

然后访问 `http://localhost:8000/`（`serve` 输出的端口可能不同）。

## 项目结构

```text
.
├── index.html              # 首页、对话区和个人中心抽屉
├── profile.html            # 八字档案新增/编辑页
├── chat.html               # 旧对话入口，跳转到首页
├── styles.css              # 全站样式、响应式布局和动效
├── shared.js               # 本地状态、存储迁移和数据 API
├── app.js                  # 首页交互、模拟回复和抽屉逻辑
├── profile.js              # 档案表单、校验和删除逻辑
├── assets/                 # 国风插画、头像和功能图标
├── .github/workflows/      # GitHub Pages 部署工作流
└── .openai/hosting.json    # OpenAI Sites 项目标识
```

脚本加载顺序很重要：业务页面应先加载 `shared.js`，再加载对应的页面脚本。共享状态以 `window.GuoxueApp` 暴露。

## 数据与限制

所有状态均写入 `localStorage`，存储键使用 `guoxue*V2` 命名，并会迁移旧版聊天记录和额度数据。主要限制如下：

| 数据 | 限制 |
| --- | ---: |
| 每日对话额度 | 10 次 |
| 单个会话消息 | 40 条 |
| 历史会话 | 90 个 |
| 八字档案 | 20 份 |

当 `localStorage` 不可用时，应用会退回到当前页面生命周期内的内存存储。清除站点数据、使用另一台设备或更换浏览器后，已有数据不会保留。

八字档案目前只负责保存用户填写的信息，不会自动换算公历/农历，也不会生成排盘结果。

## 开发说明

- 页面语言为简体中文，源文件统一使用 UTF-8。
- 视觉尺寸以移动端设计稿为主，并通过 CSS 自定义属性和媒体查询适配屏幕。
- 新增交互时优先延续 `data-action`、事件委托和 `pressable` 状态约定。
- 修改持久化结构时，应同步更新版本、标准化逻辑和旧数据迁移。
- 不要将真实密钥、敏感出生信息或生产数据写入仓库。

项目暂未配置自动化测试。提交前至少手动检查：

1. 首页在窄屏和桌面浏览器中均可正常显示。
2. 中文输入法按 Enter 不会在组合输入过程中误发送。
3. 发送问题会扣减额度、显示回复，并可从历史会话恢复。
4. 抽屉可通过菜单、遮罩、Esc 和边缘滑动打开或关闭。
5. 八字档案可新增、编辑、切换和删除，非法日期会被拦截。
6. 刷新页面后，本地额度、会话和档案仍然存在。

## 部署

仓库包含 GitHub Pages 工作流，推送到 `main` 后会发布静态文件，也支持手动触发。新增页面或脚本时，需要同步更新 `.github/workflows/pages.yml` 中复制到 `_site` 的文件列表。

项目还包含 `.openai/hosting.json`，用于关联已有的 OpenAI Sites 项目。部署时应复用其中的 `project_id`。

## 隐私提示

出生日期、时间和地点属于个人信息。当前实现只在浏览器本地保存这些内容，但正式上线前仍应补充清晰的隐私说明、数据删除机制、安全评审和必要的合规措施。
